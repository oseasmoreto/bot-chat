# ADR-0003 — DDD com bounded contexts e camadas

- **Status:** Aceito
- **Data:** 2026-09-29

## Contexto
O backend será a base para **fluxos** e **integrações** com parceiros — domínio que vai crescer. Precisamos de isolamento entre áreas e testabilidade.

## Decisão
- Código em `api/contexts/<nome>/` (bounded contexts), cada um com `domain`, `application`, `infrastructure`, `presentation`.
- Domínio em Python puro; ports como `typing.Protocol`; adapters injetados no composition root (`container.py`).
- Fronteiras verificadas por `import-linter` no CI; `core/` como *shared kernel* mínimo.

## Alternativas consideradas
- **Estrutura por camada técnica global** (`routers/`, `services/`, `models/`): mistura domínios quando cresce.
- **Framework de DI:** desnecessário agora; um dataclass `Container` basta.

## Consequências
- Mais arquivos por endpoint (aceito em troca de consistência).
- Casos de uso testáveis sem FastAPI.
- Checklist de novo context no [README da docs](../README.md#checklist-para-criar-um-novo-context).
